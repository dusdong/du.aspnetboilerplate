# 映射补丁候选消费增量

## ADDED Requirements

### Requirement: 内建集合映射的业务结果与顺序无关

引擎 SHALL 在业务类型、成员配置和输入等价时，按既有深度和引用规则映射普通集合。交换互不冲突的类型映射的注册或预热顺序，应得到相同且符合预期的业务结果。消费者可继续使用普通 `Map` 调用。

#### Scenario: 共享集合类型的两个业务成员先后映射

- **WHEN** 两个包含同种集合成员的类型映射共享普通元素映射，其中一个包含成员的映射配置了深度限制。消费者使用新建等价配置，固定注册顺序，只交换预热调用顺序，再对等价输入和目标状态执行同一映射
- **THEN** 候选均返回预期的成员值、元素数量、顺序及深度边界，普通调用无需额外映射选项

#### Scenario: 冷启动交换配置注册顺序

- **WHEN** 消费者使用新建等价配置，无预热，只交换同一组关联类型映射的注册顺序，再对等价输入和目标状态首次执行同一映射，随后重复调用
- **THEN** 候选两种顺序的首次和后续结果均符合相同的预期；包含成员或元素自身启用深度或引用保持时，约定的截断和引用身份仍成立

#### Scenario: 核对旧版运行确实加载公开包资产

- **WHEN** 独立消费者通过精确 `PackageReference` 引用 `Du.AutoMapper [14.0.0]`，在隔离空缓存从 nuget.org 还原并执行旧版对照
- **THEN** 实际还原图中的身份、资产及来源符合预期，实际还原 `.nupkg` 的 SHA-256 与 R4 已验公开下载摘要一致，进程实际加载路径上的 DLL 与该归档内 `lib/net8.0/AutoMapper.dll` 的 SHA-256 一致
- **AND** 源码引用或回退、其他包、来源或摘要不符时，该次运行缺少发行包行为证据，应修正输入并复测

#### Scenario: 正式冻结前验证顺序影响及候选结果

- **WHEN** 用已对账的公开旧包和实际候选主包，在隔离的普通 `Map` 路径上按预先确定的有界业务输入与预期独立运行上述成对顺序，并按原条件重复确认
- **THEN** 正式冻结及交接须有至少一对旧包结果或异常仅因注册或预热顺序变化而稳定不同，且至少一侧偏离预期。实际候选在同组条件下均符合预期。报告记录已复现的因素、用例条件、两侧结果或异常和实际加载 DLL 的路径及 SHA-256
- **AND** 若各顺序出现相同错误，报告保留已证实的业务偏差，顺序影响仍待证。若未观测到偏差，报告列出已试条件。顺序影响待证时回到维护评估，分析和探索性构建可继续

### Requirement: 补丁组合保留精确依赖与发行身份

维护者 SHALL 为引擎、Collection、适配器的主包和符号包冻结新的批次，逐项登记包版本、生产来源与摘要。固定模板中其余维护包继续采用已验的 R4 公开版本。

#### Scenario: 三包冻结前验收实际引擎候选

- **WHEN** 在 macOS ARM64 干净检出上制备并验收实际引擎候选，三包批次尚未生成
- **THEN** 保留普通 Release 和候选构建对原版 `AutoMapper 13.0.0` 的 ApiCompat，并通过第二项 ApiCompat 比较，左侧为已验公开 `Du.AutoMapper 14.0.0` 主包的 `lib/net8.0/AutoMapper.dll`，右侧为实际候选主包的对应 DLL。记录各自结果、包及程序集身份、资产路径与 SHA-256
- **AND** 引擎验收从验收端独立登记的本轮引擎主包及包内 DLL SHA-256 读取预期值，核对还原归档、包内 DLL、Release 输出和进程实际加载，再按既有证据边界运行三则公告的回归
- **AND** 正式冻结时逐项对账已验引擎实物与摘要，有字节变化时重验受影响项后再冻结

#### Scenario: 只直接引用候选适配器

- **WHEN** 独立消费者从空缓存仅直接引用候选适配器
- **THEN** 发布物的 nuspec 和实际还原图均满足四条精确依赖：适配器引用候选引擎、候选 Collection 和 R4 内核，Collection 引用同一候选引擎。按键更新后进程只加载一份预期引擎，包内、编译、输出和实际加载的映射 DLL 能逐项对账

#### Scenario: 候选组合混入旧输入

- **WHEN** 保留旧适配器或旧 Collection 的引擎约束，或替换一个候选包却沿用原批次登记
- **THEN** 验收在依赖范围、来源或摘要检查时失败，并指出包和不一致项；强制覆盖传递版本所得的还原结果不能登记为通过

### Requirement: 固定模板的补丁结论绑定同批实包

模板验收 SHALL 将两代 Web.Host 和 Migrator 的实际包图、Release 资产、按需加载状态和业务观测绑定到同一份补丁组合。报告分别列出本轮实测及引用的历史证据。

#### Scenario: 新库安装及同库接续

- **WHEN** 用固定模板在独立新库上执行 `net10.0` 安装，并在独立迁移用例中由 `net9.0` 向 `net10.0` 接续同一 SQL Server 库
- **THEN** 新库迁移及 Host HTTP 检查通过，两代的 Host 和 Migrator 分别核对 13、10 个维护包。冻结客户端复验租户登录和授权用户查询，记录命中的数据库、预期用户及迁移前后数据变化

#### Scenario: 在固定运行时与同库上切换补丁并回退

- **WHEN** 固定模板在同一个隔离 SQL Server 库上按 `net10.0` 依次运行完整的公开 R4 组合、三个候选加十个 R4 包、完整的公开 R4 组合，并在首阶段写入可识别的业务记录
- **THEN** 候选和回退阶段均通过授权查询命中同一数据库、租户和业务记录，确认记录身份与数据。三阶段分别对账 Web.Host 和 Migrator 在各自入口范围内的包图、编译、Release 输出及按需实际加载，回退恢复公开 R4 的包版本及资产
- **AND** 记录旧版集合行为的局限、三阶段数据库状态与写入边界。若另行验证备份恢复，另记所选恢复点及其后的写入影响
