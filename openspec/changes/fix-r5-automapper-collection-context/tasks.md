# R5 集合映射补丁候选任务

每次空缓存还原前，按当轮用量检查实际临时目录、缓存和证据目录的可写性及可用空间。

## 1. 引擎行为对照与修复

- [ ] 1.1 在 AutoMapper 子仓编写普通 `Map` 回归，预先确定有界业务输入、预期、注册及预热调用。以隔离的独立消费者运行已验公开 `Du.AutoMapper 14.0.0`，记录冷启动、两个预热方向和两种注册顺序的结果或异常及实际加载 DLL 摘要，确认至少一个可重复的旧版偏差。差异未建立时记录未成立的条件和待验证状态，回到维护评估。初步分析和探索性构建可继续，正式冻结及交接须等待差异证据。
- [ ] 1.2 基于固定 14 源码独立修正包含成员和元素的上下文处理，记录补丁来源、许可和署名。用同一组业务输入核对修复前后结果，并验证两方各自需要上下文、默认及显式深度与引用保持时的预期行为。
- [ ] 1.3 制备 Release 引擎主包与符号包，保留原版 `AutoMapper 13.0.0` 的 ApiCompat，另以已验公开 `Du.AutoMapper 14.0.0` 主包的 `lib/net8.0/AutoMapper.dll` 为左侧、实际候选主包对应 DLL 为右侧执行 ApiCompat，保存两项基线结果、身份、摘要和复跑入口。三包冻结前显式消费验收端独立登记的本轮引擎主包及包内 DLL SHA-256。核对签名身份、公共 API、目标框架、PDB、还原归档及包内、输出、实际加载 DLL 的摘要，以同条件复跑 1.1，确认实际候选纠正所观测偏差，并按原有证据边界复验三则公告。

## 2. 三包冻结与独立消费者

- [ ] 2.1 先由 Collection 子仓精确引用引擎候选，再由经典框架子仓制备适配器。分别执行组件回归并核对实际 nuspec 的四条精确依赖，尤其是适配器对 `Du.Abp [10.5.1]` 的边。正式冻结前确认 1.1 与 1.3 的实包差异和验收结果，对账引擎实物和摘要。有字节变化时以新实物重验受影响项。冻结三对归档、生产来源和各文件摘要，由验收端独立登记批次摘要。
- [ ] 2.2 在主仓以空缓存、精确包源和单一适配器直接引用启动 ABP，核对四条依赖、Castle 和静态入口、唯一引擎、对象更新、按键增删改与 SQLite 投影。分别验证旧精确边混入或同名归档被替换会被拒绝，R4 复跑仍接受原固定输入。

## 3. 模板验收与候选交接

- [ ] 3.1 在固定模板中使用三份新候选与十份 R4 公开包，核对两代四入口的还原、编译、Release 输出和实际加载。实跑 `net10.0` 新库安装以及从 `net9.0` 到 `net10.0` 的同库接续，核对迁移、Host 响应、租户登录及授权查询的数据与目标库。
- [ ] 3.2 在固定 `net10.0` 和同一个隔离 SQL Server 库上，实跑完整公开 R4 的 13 包组合、三个候选加十个 R4 包、完整公开 R4 三阶段。首阶段写入可识别的业务记录，候选及回退阶段用授权查询核对同一记录、库和租户。各阶段按既有入口范围核对包图、编译、Release 输出及按需实际加载，记录旧版集合行为的局限和写入边界。把旧包与候选的对照、各仓来源、批次摘要、消费报告及未执行项接入维护文档，列明公开发行的独立交接条件。执行 `openspec-cn validate --all --strict --no-interactive` 并核对文档链接。

## Workflow follow-up

- 三包候选实测通过后同步稳定规范并归档。公开 tag、上传、公开源回装与 GitHub Release 由相应发行变更接续。
