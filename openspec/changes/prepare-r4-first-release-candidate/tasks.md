# R4 首次发行候选任务

## 1. 固定包范围与版本

- [x] 1.1 在主仓建立 R4 组合清单。从 R3 冻结归档复核 13 个 ID、各 TFM 的全部内部和第三方依赖，按设计写入稳定版本映射与范围、各包的维护版主页，列出三个生产仓和消费模板。以旧精确范围和缺失内部边验证清单检查能指出具体差异。

## 2. 从生产提交生成实际包

- [x] 2.1 在框架子仓提供显式的 R4 打包路径，生成五个双目标核心包、两个集成包和三个 Module Zero 包及其符号包。核对十份 nuspec、默认项目构建和历史候选入口，记录 SDK、组件回归、实际依赖来源与命令。
- [x] 2.2 在映射引擎及 Collection 子仓提供 R4 打包路径，先验证引擎的稳定主包和符号包，再用该归档编译和测试 Collection。核对许可、ApiCompat、程序集身份、Source Link 或等效的提交级源码定位，以及 PDB 与 DLL 的匹配。
- [x] 2.3 在框架子仓使用已生产的核心和映射实包生成 Du.Abp.AutoMapper 及符号。用实际归档运行映射配置、原对象更新、按键集合更新和关系型投影，核对适配器的三条精确内部边。在对应子仓文档登记可重放的命令。

## 3. 冻结待发实物并验证消费者

- [x] 3.1 将三个生产仓的最终提交与主仓记录的 gitlink 对齐，从干净检出按依赖顺序生产完整批次。逐包核对 nuspec 仓库/commit、许可、TFM、DLL/API 和符号文件，写出 26 份归档的大小、SHA-256 和复核结果。验证错提交、错配 PDB 或同版本内容被替换会失败。
  冻结前解包核对 13 份 nuspec 的 `id`、`projectUrl` 和随包 README 中的安装命令、安装链接及维护入口，核实上游署名与许可。用上游主页或仍安装 `AutoMapper` 的说明验证检查会拒绝该批并定位错误。
- [x] 3.2 用已冻结归档和独立空缓存构建固定模板的 .NET 9 / .NET 10 Web.Host、Migrator。逐入口查验受控源、依赖闭包、SDK 裁剪、编译与运行资产。覆盖缺包或旧候选混入的负例。将既有核心 SQLite、SignalR、文件日志、Module Zero 和映射定向消费结果绑定到同批文件及实际环境。
  用 3.1 冻结的 `Du.AutoMapper` 复跑[三项安全修复的实包验收](../../specs/automapper-package-consumption/spec.md#scenario-判断安全修复能否纳入候选)。逐项记录主包与实际加载 DLL 的 SHA-256，核对包内 DLL，并按既定组合证据记录 CLR 低栈分支的观测边界。三项均通过后方可交付。
- [x] 3.3 运行本轮维护版的安装、同库升级与原版两条回退路径。核对实际进程、SQL Server 连接、授权、关键词查询、登录行及前后备份。验证回退入口能拒绝与本轮清单不符的升级报告或备份，并保持历史 R3 验证仍能读取原输入。

## 4. 交付本地发行候选

- [x] 4.1 以实际通过的组合生成发布说明草案、包和符号摘要、命令、支持矩阵、已知限制与后续发布清单。核验所有报告使用同一批归档，运行相关回归、主仓 Python 自检和 `openspec-cn validate --all --strict --no-interactive`。按实际结果更新文档入口和 R4 路线状态，保留公共源发布与公开源回装的待办。
