# 部分包升版的公开发行准备

## ADDED Requirements

### Requirement: 局部补丁可从已验候选交接为本地待发批次

维护者 SHALL 用一份可独立校验的清单区分本次上传件与沿用的公开依赖，给出每个变更归档的来源、实际差异和相应复验，以及面向公开源用户的安装说明。发布前演练与真实公开回读分别登记。

#### Scenario: 三个映射包升版

- **WHEN** 已验组合中的引擎、Collection 和适配器拟公开发行，另外十个维护包使用 R4 的公开版本
- **THEN** 待发清单逐一列出三个包的版本、六份上传归档的摘要、目标程序集与三个 PDB、编译源码和生产树，并引用十个沿用包的公开验签下载记录。上传队列仅包含三个新包，各目标 nuspec 的四条内部精确依赖与实际还原图一致
- **AND** 维护者可从三个实际主包读到对应包 ID 和版本的公开安装方式。包内仍要求配置维护者本地源时，交接指出包和文件，待修正并复验后再列为待发

#### Scenario: 为公开发行重新制备归档

- **WHEN** 修改安装说明、重建或签名导致归档字节变化
- **THEN** 保留原冻结记录，独立登记新清单摘要。列出归档成员及内容差异，核对 DLL、PDB、nuspec、Source Link、许可和包源。实际待发件通过空缓存还原及相应消费复验。输入和断言相同的历史结果按原批次注明，变化所影响的行为有对应实测
- **AND** 引擎从包含公开安装 README 的干净新提交制备。交接登记该提交、Git 树和打包的 `RepositoryCommit`，核对 nuspec 的 `repository/@commit`。交接可核对拟用 tag 名、目标主仓提交及三个生产 gitlink。主仓尚未固定新引擎时，交接给出实际 gitlink 与制包来源的差异及打 tag 前的待办，标明目标待定

#### Scenario: 在本地演练发布顺序和部分上传

- **WHEN** 使用待发清单和独立的演练记录，模拟某个依赖已受理、未索引或公开内容不符
- **THEN** 后续包只在其直接内部依赖有匹配版本、公开下载、验签和内容对账证据后具备上传条件。再次执行能从各包已有状态继续，并指出缺失或冲突的证据。符号按目标分别跟踪
- **AND** 引擎及 Collection 已通过时，`Du.Abp [10.5.1]` 的 R4 验签下载证据缺失或摘要不符均暂停适配器。补正后沿用原进度及已确认项，上传队列仍仅含三个新包

#### Scenario: 演练交付用的公开消费命令

- **WHEN** 在隔离目录用 R4 已签名实物和隔离样本执行将交付的同一条 R5 纯 nuget.org 消费命令
- **THEN** 匹配的清单、冻结批次、下载登记和公开源资产通过校验，混入本地源或使用错误批次时各自被拒绝，并记录具体原因
- **AND** 交接状态为本地待发。三个 R5 主包的公开匿名下载、验签与内容对账、三个 PDB 的符号服务回读、两代 Web.Host 与 Migrator 四入口的空缓存纯 nuget.org 还原及隔离库业务在实际公开后验证，并据实际结果完成发行说明
