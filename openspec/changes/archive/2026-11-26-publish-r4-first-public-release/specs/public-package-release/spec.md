# R4 首次公开发行

## Purpose

让使用经典 ASP.NET Boilerplate 的维护者可以从公开 tag 找到首发版本的源码、包和符号，并能在隔离环境中仅用公共包源复现已声明的模板运行结果。发布者和消费者都能核对公开文件与本地通过验收的批次之间的对应关系。

## ADDED Requirements

### Requirement: 发行身份和发布权限可核对

发行记录必须（SHALL）将主仓 tag 指向的提交、三个生产 gitlink、批准的发布者与目标、冻结批次及 26 份上传输入的身份和摘要关联起来。

#### Scenario: 输入和授权均已就绪

- **WHEN** 发布者取得本批次对主仓 tag、GitHub Release 及 nuget.org 包与符号的相应授权，且核对了账号权限、名称和版本
- **THEN** 发行记录列出主仓 tag 目标、11 个框架包及两个映射包的确切版本、生产提交和各自的主包及符号包摘要，允许执行已授权步骤

#### Scenario: 外部写入前发现差异

- **WHEN** 授权缺失、同名 tag 指向其他提交、生产 gitlink 不符，或待上传归档的字节与冻结登记不符
- **THEN** 发布者在受影响的公开操作前停止，并记录需要解决的具体差异

### Requirement: 部分发布后可以安全续作

发布者必须（SHALL）分别登记 tag、每个主包、每个符号包与 GitHub Release 的外部状态。上传主包前，发布者必须（SHALL）确认其冻结 nuspec 各目标组引用的每个直接内部依赖均已按本批版本通过匿名下载、仓库验签与冻结内容核对。

#### Scenario: 上传结果不确定或索引延迟

- **WHEN** 上传超时、服务已受理但索引仍不可见，或进程在部分上传后中断
- **THEN** 后续执行先回读对应包和符号的服务状态，保留已确认项，并逐项记录待核对或待上传的身份。已受理的包须经独立下载验证后才能登记公开可消费

#### Scenario: 上游主包已受理但尚未核验通过

- **WHEN** `Du.AutoMapper 14.0.0` 已受理，但尚不能匿名下载或未通过仓库签名及逐文件核对
- **THEN** 暂停上传 `Du.AutoMapper.Collection 11.0.0` 及依赖它的主包，记录阻塞的依赖和版本。独立且已满足自身依赖条件的主包可继续上传
- **AND** 引擎核验通过并登记其公开下载 SHA-256 后即可上传 Collection，即使引擎的符号仍待索引

#### Scenario: 目标版本已存在

- **WHEN** 公开源已有相同 ID 和版本
- **THEN** 发布者核对所有者、该批发布记录及公开内容。已证明属于本次发行的项目可接续，归属或内容有冲突的项目停止发布并保留证据

### Requirement: 公开主包和调试符号可追溯到冻结输入

核验记录必须（SHALL）关联每个主包的上传摘要、公开下载摘要、经过信任验证的 nuget.org 仓库签名及内容核对结果，并提供每个发行目标的符号服务读回结果。

#### Scenario: 公开仓库对主包签名

- **WHEN** 消费者匿名下载该版本，仓库签名改变了归档字节
- **THEN** 核验器验证仓库签名及签名来源，按路径逐项对照冻结包内文件的集合与内容。通过时保留上传和下载两份摘要及签名差异的解释

#### Scenario: 主包内容存在额外差异

- **WHEN** 签名无法验证、公开主包缺少一个文件、出现签名以外的新文件，或已有 DLL、nuspec 等文件的内容发生变化
- **THEN** 即使版本号相同也将该主包记为核验失败，报告包、路径或签名原因，保留两个版本的摘要以便定位

#### Scenario: 调试器请求符号

- **WHEN** 使用公开主包中的 DLL 向 nuget.org 符号服务请求其 Portable PDB
- **THEN** 按包、目标框架及 DLL 记录读取结果，将调试标识与 PDB 内容核对至相应的冻结符号。18 个目标全部匹配后才登记符号验证通过

### Requirement: 公开源消费结果决定发行完成状态

项目必须（SHALL）在干净的固定模板中从 nuget.org 独立还原公开版本，记录四个 Release 入口的资产与进程结果，以及 SQL Server 和 Angular 代表性业务的实际观测。发行说明必须提供普通消费者可用的版本、命令、链接和实测范围。

#### Scenario: 两代模板从公开源运行

- **WHEN** 分别用空缓存和仅含 nuget.org 的包源配置运行固定模板的 `net9.0` 和 `net10.0` Web.Host 与 Migrator
- **THEN** 两代还原图分别包含 Host 所需的 13 个和 Migrator 所需的 10 个维护包。构建、启动、数据库迁移、两代同库接续、租户登录及授权查询均有实际结果，每个入口按包 ID 和版本将缓存中实际还原的 `.nupkg` SHA-256 与已验签并经内容核对的公开下载 SHA-256 比对。编译引用、Release 输出和进程实际加载的维护 DLL 均匹配所选冻结资产的 SHA-256。按需依赖记录输出及实际加载状态

#### Scenario: 混入本地资产或缺少公开证据

- **WHEN** 还原使用了本地源、旧缓存、维护组件的项目引用，缓存主包与已验签的公开下载摘要不符，维护 DLL 与冻结资产摘要不符，或仍有主包、符号或消费者结果待核实
- **THEN** 该次运行不能登记为首次公开发行验收通过，记录受影响的入口、包或资产及失败原因，列出待补证据

#### Scenario: 普通消费者按发行说明完成新安装

- **WHEN** 消费者匿名取得固定模板，在干净目录使用独立空 NuGet 缓存、仅含 nuget.org 的包源配置、新建的空 SQL Server 测试库和发行说明草案列出的公开材料，逐条执行 `net10.0` 安装命令
- **THEN** Migrator 成功退出且新库可查到模板迁移记录，Web.Host 启动并返回说明约定的 HTTP 成功响应。记录实际执行命令和结果，供发行说明引用
- **AND** 说明中用到的发行 tag 之后新增的脚本可按固定提交匿名取得。若需读取发布者交接目录、历史运行报告、验证机冻结的 Angular 输出或数据库备份，或任一步骤无法按说明完成，须修订说明或入口并重新通过本场景后才能发布 GitHub Release

#### Scenario: 发布可供用户采用的发行说明

- **WHEN** 13 个主包、13 个符号包、18 个符号目标、两代公开源业务回归及普通消费者按发行说明的新库安装均已通过验证
- **THEN** GitHub Release 关联已核实的主仓 tag、三个生产提交、包页面、可公开的摘要、安装命令和实测支持矩阵，并标明本次公开源实测与此前本地回退证据的来源。新安装示例使用 `net10.0` 并注明实测运行时 `10.0.15`。`net9.0` 标为存量应用迁移兼容性实测，注明实测运行时 `9.0.10` 及微软结束支持的日期 `2026-11-10`
