# 首次公开发行任务

## 1. 准备首发清单和验收入口

- [x] 1.1 在主仓用交接根目录的固定校验表和 `eng/r4_candidate_batch.py verify` 复核发布输入，生成含主仓 tag 目标、三个 gitlink、13 个包版本、26 份输入摘要及内部依赖顺序的首发清单。用实际 nuspec 核对顺序，并确认替换任一归档都会中止预检。
- [x] 1.2 准备公开主包、符号及发布进度的逐项核验入口与复跑说明。用隔离样本确认包内容差异、错误 PDB、超时待索引和已有版本冲突可定位到具体包或目标，重复执行保留已确认记录。模拟引擎已受理但不可下载或内容核验失败，确认 Collection 暂停、无关主包可继续，并在引擎核验通过后恢复。
- [x] 1.3 为固定模板提供仅用 nuget.org 的还原入口，复用原四入口的构建、程序集和业务断言。公开模式按 ID 和版本核对缓存主包与已验签公开下载件的 SHA-256，按目标资产核对编译、输出及实际加载的 DLL 与冻结 DLL 的 SHA-256。用签名后整包摘要变化且内容匹配的样本验证通过路径，用缓存主包或 DLL 摘要错误、本地源或旧缓存混入的样本验证失败路径，复核本地冻结源模式。准备仅依赖公开材料的新库安装说明草案。

## 2. 向公开目标交付已授权输入

- [x] 2.1 在首次外部写入前回读主仓 tag、13 个 ID/版本和服务发布端点，确认发布者对相应 GitHub 与 NuGet 操作的授权和权限。记录账号、目标及冲突处理结果，核实 tag 权限、包名可用性与首发归属。
- [x] 2.2 为主仓指定提交发布附注 tag `v10.5.1`，回读远端 tag 解引用后的完整提交和三个 gitlink。若 tag 已存在，核对目标和来源后续作；冲突时保留原 tag 并记录阻断原因。
- [x] 2.3 按首发清单从交接目录上传 13 个主包和各自的符号包，分别记录上传摘要、受理和索引结果。上传下游主包前，用 1.2 的核验入口匿名下载其全部直接内部依赖的本批版本，完成验签、冻结内容核对并登记公开下载 SHA-256。依赖待索引或失败时暂停对应下游，其他依赖条件已满足的包可继续。遇到断点或重复版本，回读所有者和内容后续作。

## 3. 以普通消费者身份验证发行

- [x] 3.1 汇总 2.3 中已完成的匿名下载记录，补验其余主包，使 13 个主包各有 nuget.org 仓库签名、证书链、时间戳、逐文件内容及上传和下载两份 SHA-256 的核验记录。用公共符号服务取得 18 个目标的 Portable PDB，核对 DLL 调试标识和冻结 PDB 摘要，逐项记录可复查的结果。
- [x] 3.2 用独立空缓存从 nuget.org 还原固定模板的两代目标，Release 构建并运行各自的 Migrator 和 Web.Host。逐入口保存包源、13/10 个维护包的依赖与资产，将每个缓存主包绑定到 3.1 的已验签下载摘要，将各入口编译、输出及实际加载的 DLL 绑定到对应冻结资产摘要，记录按需依赖的实际加载状态。执行两代同库迁移、租户登录和授权用户查询，核对唯一用户 ID 3、查询目标库及候选库和对照库的登录计数。
- [x] 3.3 在单独干净目录按发行说明草案的 `net10.0` 命令实跑。匿名取得固定模板及所需脚本，使用独立空缓存、nuget.org 和新建的空 SQL Server 测试库，检查 Migrator 成功退出、新库有模板迁移记录、Web.Host 返回约定的 HTTP 成功响应。记录命令、公开输入提交及结果。若命令依赖 tag 后新增的脚本，用固定提交链接取用。若依赖内部交接材料或命令执行失败，修正并重跑。
- [x] 3.4 复核 3.1 至 3.3 全部通过后，以已验证的 tag 发布 GitHub Release。回读包链接、源码提交、安装命令、摘要、符号入口、回退说明和支持矩阵。新安装示例列 `net10.0` 和实测运行时 `10.0.15`，`net9.0` 列为存量应用迁移兼容性实测，注明运行时 `9.0.10` 和微软结束支持日期 `2026-11-10`。更新 README、文档索引与维护路线。用发行说明中的入口重查可见性，登记发布标识和时间，完成 OpenSpec 严格校验。
