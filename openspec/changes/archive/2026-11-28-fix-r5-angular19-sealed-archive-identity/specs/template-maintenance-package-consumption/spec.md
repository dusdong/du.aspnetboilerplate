# Spec Delta

## ADDED Requirements

### Requirement: 匿名启动双包输入报告准确标记封存归档

固定 Angular 19 模板的双包输入核验 SHALL 分别记录实际归档 SHA-256、封存原件匹配状态以及包内文件和实装证据。封存原件匹配状态 SHALL 由实际归档 SHA-256 与对应原件登记摘要比较得出。输入通过 SHALL 满足既有归档内容、实装、冻结锁、production 文件清单及同次构建来源要求。

#### Scenario: 验收通过的两份封存原件均被识别

- **WHEN** 匿名启动的双包输入核验收到已验收的适配器、资源包封存原件及配套实装和构建
- **THEN** 两包实际 SHA-256 各自匹配已交付双包指南中独立登记的原件摘要，报告的 `matchesSealedArchive` 均为 `true`，输入核验通过

#### Scenario: 仅适配器重包装时按实际归档校验冻结锁

- **WHEN** 只改变适配器 `.tgz` 的包装字节，资源包原样保留，两包的完整文件路径和字节均匹配登记内容及实装，其他冻结输入及构建证据均吻合
- **THEN** 沿用仍指向适配器原件 SHA-1 的旧锁时，双包输入核验拒绝该组合
- **AND** 保留同一对归档，只把适配器 `resolved` 项的归档 SHA-1 改为实值后，输入核验通过。报告记录重包装归档的实际摘要，适配器的 `matchesSealedArchive` 为 `false`，资源包的标记为 `true`

#### Scenario: 归档内容与登记不符时输入受阻

- **WHEN** 包内路径或字节偏离登记内容，实装与该归档吻合，锁指向实际归档且其余冻结锁及构建条件均吻合
- **THEN** 双包输入核验在归档内容检查处拒绝该组合，匿名启动按既有输入受阻规则处理该侧

#### Scenario: 实装与归档不符时输入受阻

- **WHEN** 实装路径或字节与归档不符，归档内容与登记吻合，锁指向实际归档且其余冻结锁及构建条件均吻合
- **THEN** 双包输入核验在实装检查处拒绝该组合，匿名启动按既有输入受阻规则处理该侧

#### Scenario: 其余冻结锁不符时输入受阻

- **WHEN** 两包的锁定位均指向实际归档，内容、实装及构建证据均吻合，其余冻结锁偏离登记组合
- **THEN** 双包输入核验在冻结锁检查处拒绝该组合，匿名启动按既有输入受阻规则处理该侧

#### Scenario: 正式离线回执仅修正适配器封存标记

- **WHEN** 对 SHA-256 为 `b7b8975621708a4a355e9dbf91c0be39aecb4ee5a071b0a0876e775552cdfa49` 的历史正式报告，使用修复后的入口离线核验其两份原件、原实装及同次构建输入
- **THEN** 保留原报告并另存正式离线回执，比较两者的完整 `sides.pair.input`。只有 `packages.abp-ng2-module.matchesSealedArchive` 确实从 JSON `false` 变为 JSON `true`、资源包标记始终为 `true` 且其余字段逐层相同，离线复核才通过。任何其他字段增加、缺失或改变均拒绝
- **AND** 比较范围限于 `sides.pair.input`，封套的生成时间等元数据在范围之外。回执注明 Chrome 和 SQL Server 未重跑
