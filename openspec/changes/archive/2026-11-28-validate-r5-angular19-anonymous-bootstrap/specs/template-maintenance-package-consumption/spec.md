## ADDED Requirements

### Requirement: 固定 Angular 19 模板可对照双包候选的匿名首次启动

验收 SHALL 在各自全新的无登录态浏览器上下文中启动固定 Angular `19.2.1` 模板的双包候选与全公开冻结 production 前端。两侧使用同一本机 `v10.5.2` Web.Host、同一已准备的专用 SQL Server 测试库以及等价的前端服务和浏览器条件。

#### Scenario: 由各自已核验的 production 产物启动真实应用

- **WHEN** 两侧输入均可追溯到已登记的模板、包和构建，且共用 Host 与测试库身份已实测核验
- **THEN** 两侧首个主文档请求分别从根路径直接取得 HTTP 200 和本侧 production index，随后在同一文档内完成 Angular 导航。各自实收 HTML、入口 JS、全局脚本和应用配置匹配该侧服务副本，双包侧同时收到同次构建包含候选适配器代码的 JS，实收摘要与对应产物匹配
- **AND** 每侧服务副本只在应用配置 JSON 中覆盖本轮 `appBaseUrl` 和 `remoteServiceBaseUrl`，冻结原件保留原始摘要。V7 继续要求公开冻结实物，拒绝双包产物

#### Scenario: 新浏览器从模板根路径完成匿名初始化并显示登录页

- **WHEN** 各自的全新浏览器上下文未继承认证、租户和语言状态，打开该侧前端根路径且未填写表单或选择租户
- **THEN** 应用实际读取本侧 production 应用配置，再发送 `GET /AbpUserConfiguration/GetAll` 和 `GET /api/services/app/Session/GetCurrentLoginInformations` 到登记的 R5 Host。两个实收响应均为业务成功，所需请求按模板初始化顺序各执行一次。实际响应字段表明当前为匿名用户、宿主侧且无当前租户，保留字段的省略或 `null` 形式
- **AND** Angular 路由最终到达该侧 `/account/login`，可见用户名或邮箱控件、密码控件与登录文案。标题、提交按钮文案和两个控件占位文本与该侧实际 `GetAll` 返回的模板本地化值对应。页面未捕获异常为零。浏览器未发出登录提交、租户选择、角色操作或 SignalR 连接请求

#### Scenario: 对照结论可追溯至两侧独立实测

- **WHEN** 两侧都完成真实首次启动并符合各自断言
- **THEN** 比较匿名身份语义、初始化配置字段、当前语言、三个登录文案和 application 元数据。各自 URL 按侧核对，保留可接受的 `null` 和省略原型。模板版本须为 `9.3.0`，发布日期按同一 Host 跨侧比较。报告两侧与基线的可比性和对照结果。记录每侧实际网络与界面证据、Host 与库身份及资源终态。报告的适用范围为本次组合的匿名首次访问及已观察的初始化字段
- **AND** 证据按字段白名单保留，不写入凭据、Cookie 值、令牌或连接字符串

#### Scenario: 输入受阻或启动证据偏离

- **WHEN** 任一侧或共同输入缺失、身份或可比性无法核实，或者输入已核实而实际请求、响应、脚本、路由或界面缺失或偏离，包括服务器从根路径用 302 直接送往登录页
- **THEN** 输入未核实的侧记为输入受阻，启动不符合预期的侧记为失败。保留停止阶段、预期、实测和已有证据，依赖该条件的后续步骤标为未执行。满足自身及共同前提的另一侧独立运行。整体通过须有两侧独立通过、结果可比和资源收尾证据
