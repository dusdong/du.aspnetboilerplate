## 1. 主仓验收输入

- [x] 1.1 为两种前端和 R5 后端准备显式的输入路径与验收命令。核对封存输入或按链接从普通克隆重建，保留实际归档摘要、锁、构建统计、生产文件清单、公开准备报告和 Release 入口摘要。验证候选与公开清单分别通过各自核验，确认原 V7 校验继续拒绝双包副本。[固定输入与缺项处理](design.md#1-固定两侧输入)
- [x] 1.2 用已核验的 R5 Migrator 准备独占 SQL Server 实例中的唯一测试库，确认标准迁移、必要种子及实际库身份。启动同一环回 Host，核验监听、实际程序集与 SQL 目标，为两侧静态服务配置相同服务条件与各自 CORS。验证两份服务副本只有登记的应用配置字段被覆盖，保存实际身份及清单回执。[共用后端与服务副本](design.md#2-共享一个实际-host-和已准备的测试库)

## 2. 双侧真实浏览器对照

- [x] 2.1 实现并运行匿名首次访问。对每侧用新上下文从根路径直接取得实际 index 并同文档导航，核对实收 HTML、入口与全局脚本、候选 chunk、应用配置、两条真实匿名 API、最终路由和登录页可见文案。核对无重复初始化、未捕获异常及超出范围的请求。保存字段白名单证据。用定向验证覆盖错误脚本、非匿名或缺失的响应、任一侧输入受阻、HTTP 重定向绕行和两侧自洽却不一致的判定。[启动观测](design.md#3-观察真实启动及其可见结果)
- [x] 2.2 保存两侧独立结果、整体比较及未执行原因。验证运行结束后本轮进程、监听和专用 SQL 资源已收尾，原输入摘要可读回。记录实际执行命令、适用范围和普通克隆复跑方法，核对稳定规范与历史 V7 结果，执行主仓 OpenSpec 严格校验及文档差异检查。[判定与收尾](design.md#4-判定与收尾)

## 本轮证据

正式入口退出 `0`。两侧均取得根路径首个主文档 HTTP 200，同文档转至登录，并核对三个按序初始化 GET、匿名与可见文案。共享 Host 与唯一专用 SQL 测试库身份一致，清理读回通过。[实测与复跑](../../../../docs/maintenance/r5-angular19-anonymous-bootstrap.md)

复审返修后，公开指南的观测代码通过真实 Angular 全局脚本构建器产生九条可直接验证的记录。人为占用公开前端端口时，双包侧实际通过，占用者的监听仍可连接。修订后的正式双侧运行验证在所需回执和登录表单齐备时结束，两侧各有三个未结束的字体请求。
