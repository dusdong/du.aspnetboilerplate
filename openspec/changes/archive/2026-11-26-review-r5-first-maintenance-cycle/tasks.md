# R5 首轮维护审查任务

## 1. 固定首轮输入

- [x] 1.1 在主仓维护记录中登记审查截止时间、`v10.5.1` 的 tag 目标、公开校验清单和三个生产 gitlink，核对全部 13 个包的 ID、版本、生产仓及原上游身份，逐仓登记上游比较基点。
- [x] 1.2 从四个首发 `project.assets.json` 按 TFM 和入口提取 `type=package` 的直接和传递闭包，核对总包数、维护包数和四个防误合并样例版本。记录原图 SHA-256、提取及引入路径，随报告交付精简清单。分别登记实际进程的 .NET 与 ASP.NET Core 版本，并留存复跑与原图的差异。[图与样例](design.md#按-tfm-和入口保留完整依赖图)

## 2. 执行首轮上游与依赖审查

- [x] 2.1 对三个生产仓分别记录上游基点、实际检索的分支或发行及截止完整 SHA，核对较新维护线上适用于旧基点的修复。框架 #7219 对照发行源码与已有回归。三份既有 AutoMapper 公告逐项关联 R4 同一实际加载 DLL 的摘要和各自的实包证据，保留覆盖边界。
- [x] 2.2 将各入口直接与传递依赖的实际解析版本和实际运行时与 NuGet 公告、原上游公告及运行时服务公告对照。按来源保存查询时间和覆盖情况，命中项记录版本范围、引入路径和处理归属。空结果与未覆盖来源分别登记范围和补查条件。

## 3. 给出维护决定

- [x] 3.1 逐项登记需处理、已有修复、不适用、暂缓（含理由和触发条件）或待核实及其证据。给出维护包需补丁、无需补丁或暂不能判定的整轮决定，另列模板、运行环境和消费者行动。已确认需要修复的维护包列出优先项、目标仓、兼容与回退边界和复验入口，可先单独立项。影响决定的缺证须列明范围、补查条件和入口。[决定口径](design.md#用一份维护记录交接结论)
- [x] 3.2 将维护记录接入文档索引和维护路线，留下各来源的下轮检查点。若有适用的单独补丁变更，按手册交接待演练的 OIDC 和独立清单摘要要求。对照 R4 实测矩阵复核支持范围，检查链接并执行 `openspec-cn validate --all --strict --no-interactive`。[补丁交接](design.md#向单独补丁变更交接发行准备)

## Workflow follow-up

- 首轮维护记录验收后同步稳定规范并归档，按本轮决定接续已登记的补丁、补查或消费者验证事项。
