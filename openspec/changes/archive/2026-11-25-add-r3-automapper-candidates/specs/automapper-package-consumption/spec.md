# 映射候选包消费规范增量

## Purpose

让经典 ABP 应用可以从可追溯的映射候选包启动既有配置，并在切换维护版本时用同一组业务输入核对用户更新、集合元素身份和关系型查询结果。维护者可以按冻结的包和补丁证据复核每次兼容结论。

## ADDED Requirements

### Requirement: 三份映射候选可追溯到兼容基线

维护者 SHALL 能从候选清单核对每个主包、符号包、实际生产源码、许可与安全维护结论。

#### Scenario: 核对同一批映射产物

- **WHEN** 维护者检查三份实际候选及对应符号包
- **THEN** 清单给出各仓库、固定参考提交、实际生产提交或可重放的源码树、补丁来源及归档摘要
- **AND** 与同目标原版相比，三个组件保留程序集名称、根命名空间和公开类型全名，报告核对程序集身份（含公钥标记）、公开 API 和目标框架

#### Scenario: 在干净 macOS 检出上执行引擎 API 比较

- **WHEN** 维护者在 macOS ARM64 干净检出上分别执行普通 Release 与候选引擎构建
- **THEN** 两次构建都实际运行 ApiCompat 并通过，报告记录复跑入口、历史参考包 ID 和版本、包内 DLL 路径、包与 DLL 的 SHA-256 及两次比较结果
- **AND** 输入缺失、摘要错误、跳过比较或比较失败时，验收返回非零并指出失败阶段

#### Scenario: 判断安全修复能否纳入候选

- **WHEN** 为兼容指南登记的三则公告判定候选是否通过
- **THEN** 每一项列出适用性、修复或不受影响的依据、涉及的源码及补丁来源与许可，关联冻结 `Du.AutoMapper` 主包和加载 DLL 的 SHA-256，并保存约定行为的触发条件、预期与实际结果
- **AND** 仅 GHSA-gpwp-5797-mjff 的 CLR 低栈分支同时以三项证据验收。核对冻结主包 DLL 中 `Mapper.MapCore` 调用 `RuntimeHelpers.EnsureSufficientExecutionStack` 的 IL，核对 .NET 9 官方文档的异常契约，并在加载同一冻结 DLL 的隔离子进程中用受控异常实测应用层的传播与恢复。探针须验证收到同一个注入的 `InsufficientExecutionStackException` 对象或含该对象的包装链，同一 Mapper 随后须完成正常映射并返回预期值。报告明确记录异常由测试注入，实际 CLR 低栈触发未观测
- **AND** 其余约定行为与异常均使用冻结主包 DLL 在隔离子进程动态复验。约定可恢复时，同一子进程中的同一个 Mapper 随后完成一次正常映射并返回预期值。证据缺失、处置未解决、断言失败、非预期退出或超时均判为失败

### Requirement: 适配器的独立包闭包只加载一套映射引擎

消费者 SHALL 能只直接引用维护版适配器，从指定包源还原映射栈及 ABP 内核，使用经典 ABP 的模块和依赖解析入口运行。

#### Scenario: 从空缓存安装并启动模块

- **WHEN** 独立消费者只直接引用三个映射包中的 `Du.Abp.AutoMapper` 且通过它传递取得 ABP 内核
- **THEN** 适配器主包 nuspec 对本批引擎、Collection 和冻结 `Du.Abp` 各声明一条 `[精确版本]` 依赖，Collection 主包 nuspec 对同一引擎声明一条 `[精确版本]` 依赖。四条声明逐一命中还原图，包图中无原版映射包或上游 ABP 包回流
- **AND** 从 Castle 解析的映射服务可用，静态兼容入口可用，三份映射 DLL 的包内资产、Release 输出和实际加载文件逐一同摘要
- **AND** Castle 解析、静态入口调用和按键集合映射完成后，枚举进程内全部 `AssemblyLoadContext`，简单名为 `AutoMapper` 的程序集实例恰好一个。报告记录加载上下文、程序集全名、路径及 SHA-256

#### Scenario: 冻结输入、依赖声明或加载实例异常

- **WHEN** 传递引擎缺包、冻结包摘要错误、内部边使用最低版本范围、同名 DLL 来自另一发行包，或相同字节的引擎在两个加载上下文各有一个实例
- **THEN** 验证返回非零并指出失败阶段及对应的包、依赖边或程序集。范围错误时列明预期与实际声明，重复加载时列出各实例的上下文和路径

### Requirement: 模板既有映射配置可更新同一用户实例

消费者 SHALL 能沿用固定模板的 Profile、属性映射和配置扫描入口，对已有用户执行与原版一致的更新。

#### Scenario: 保留模板中重复声明的映射

- **WHEN** 原版与候选分别加载相同模板配置，通过 `IObjectMapper` 将同一 DTO 映射到已有角色和创建时间的用户实例
- **THEN** 两次均能完成模块启动和映射，返回原目标实例，可更新字段取得 DTO 值
- **AND** 角色集合的引用及成员、创建时间保留原值，报告记录配置和输入来源、两侧运行结果及差异

### Requirement: 按键更新保留匹配元素身份

消费者 SHALL 能按既有键配置更新目标集合，并保留原版对匹配项、新项和移除项的处理语义。

#### Scenario: 通过经典 ABP 的键标记更新集合

- **WHEN** 原版与候选使用同一组独立的集合测试类型，启用 `AddCollectionMappers` 和 ABP 的 `AutoMapKey` 配置，对含保留项和待删除项的目标集合映射包含更新项和新项的输入
- **THEN** 两侧得到相同的键和值，匹配项保留原对象引用，新项出现一次，删除项消失，集合实例行为与原版一致
- **AND** 候选进程按程序集名加载的 Collection 来自本批主包

### Requirement: 查询投影在关系型数据库上执行

消费者 SHALL 能通过经典 ABP 的 `IObjectMapper.ProjectTo` 在关系型数据库执行查询，并取得与原版一致的投影结果。

#### Scenario: 比较同一查询的两次数据库结果

- **WHEN** 原版与候选在相同 SQLite Provider 版本及种子上筛选并排序模板 `User` 查询，通过 `IObjectMapper.ProjectTo<UserDto>` 投影后物化
- **THEN** 两侧的实际执行 SQL 均包含约定的筛选和排序，结果行、字段值及顺序命中已知预期，报告保留 Provider 版本、执行 SQL 和参数
- **AND** 从原版投影表达式和实际执行 SQL 确认取列及 `FullName` 的计算位置。候选取列或计算位置发生变化时，即使返回值一致也判为失败，并指出差异。SQL 别名和空白允许差异

### Requirement: 冻结批次可独立复验

维护者 SHALL 能按验收报告重跑同一批映射候选，并定位缺失的输入或未通过的业务断言。

#### Scenario: 复跑冻结候选

- **WHEN** 使用登记的原包、独立空缓存和相同输入重新运行消费验收
- **THEN** 报告给出实际运行环境、解析版本、包摘要和各项业务断言结果。任一必需断言未执行或失败时，入口返回非零并注明阶段
