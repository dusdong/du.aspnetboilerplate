# R3 AutoMapper 实施任务

## 1. 固定输入与原版业务对照

- [x] 1.1 核对主仓及三个生产仓的提交、两份兼容参考的许可、可用 R3 序号和 R2 / Module Zero 实物摘要，登记各组件普通及候选包的目标框架、身份、版本与依赖边。在 macOS ARM64 干净检出上验证普通引擎 Release 的 ApiCompat 入口，固定参考包 ID、版本、包内 DLL 路径和两份 SHA-256，留存实际比较结果。
- [x] 1.2 使用模板固定文件与原版 ABP `10.2.0`、AutoMapper `14.0.0`、Collection `11.0.0`，在独立进程验证配置扫描和已有用户更新。用独立测试类型验证 `AutoMapKey` 集合。对 SQLite `User → UserDto` 投影保存表达式、实际 SQL、参数、取列、筛选、排序、`FullName` 计算位置和结果。登记文件摘要、断言及实际包图，复跑确认原版基线。

## 2. 三个子仓按依赖顺序生产候选

- [x] 2.1 在 AutoMapper 14 固定源码上逐项处置指南登记的三则公告，登记适用性、处置依据、补丁来源及许可、约定行为和源码验证结果，运行受影响的正常映射回归。
- [x] 2.2 用 1.1 的固定参考输入执行候选引擎 ApiCompat，保存结果，生成 `Du.AutoMapper` 及符号包，核对目标、程序集身份、公钥标记、公开 API 和许可。按增量规范核验 2.1 各项约定，记录包和加载 DLL 的 SHA-256、实际行为、退出状态及超时情况。仅 GHSA-gpwp-5797-mjff 的 CLR 低栈分支采用实包 `Mapper.MapCore` 的 IL、.NET 9 官方异常契约及同一冻结 DLL 的受控异常传播和同一 Mapper 恢复实测，注明实际低栈触发未观测。其余约定在隔离子进程动态复验，可恢复失败后用同一进程、同一个 Mapper 验证正常映射。将生产与验证命令记入子仓说明。
- [x] 2.3 在 Collection 11 固定源码上使用实际引擎候选编译、测试并生成 `Du.AutoMapper.Collection` 及符号包。检查其精确引擎依赖、编译引用与包内 DLL 身份，保留集合更新回归结果与生产命令。
- [x] 2.4 在经典框架以两份映射候选及 R2 内核原包编译、生成 `Du.Abp.AutoMapper` 及符号包，核对三条直接依赖。运行普通项目构建及 `Abp.AutoMapper.Tests`，记录普通与候选身份、生产命令及三仓源码树与产物摘要。
