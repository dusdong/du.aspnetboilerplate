- [x] 1.1 在 `eng/verify.py` 实现 `--profile r0`，读取已接受 R0 清单，预检工具、实际 SDK、宿主和固定框架对象，初始化独立目录及机器可读报告。以框架 gitlink 已推进到 R1 的主仓检出验证报告中的主仓输入、gitlink、固定 R0 输入与当前检出各自正确。分别核对当前主仓和框架检出运行前后原样保留，以及已接受历史基线内容运行前后相同。用临时夹具模拟固定对象缺失或 SDK 不匹配，确认非零退出且报告标明未执行阶段。
- [x] 1.2 将现有脚本整理为可分别调用的物化及还原和已还原 `primary` 续跑阶段。保留旧 `primary` 完整及 `repeat` 仅还原调用与路径。统一入口先完成两次独立干净还原和三方比较，一致后沿用主轮目录、包目录及还原产物。两轮分别取得 11 个项目和 11 个 `net9.0` 目标，包来源、内容哈希及依赖清单均匹配基线。用一份实际还原清单的临时副本改变一个传递包版本，断言非零退出、报告定位具体项目、目标和版本差异，且构建、API、.NET 回归均未启动并标为未执行。
- [x] 1.3 核对五个项目的原 `PackageId`、版本、`AssemblyName`、`RootNamespace`、目标框架及内部引用，再用主轮还原构建 Release。用实际五个 DLL 验证摘要、重复提取与 API 比较。复用手册中的公开方法参数变异，在临时清单上确认同名程序集的签名差异被定位，统一入口传播非零。缺少 DLL 或求值结果时，报告指出缺失项目及证据路径。
- [x] 1.4 从同一主轮构建执行三个完整测试套件，核对 .NET 测试退出码、三份当次 TRX 明细和关键汇总计数，按两个完整测试名匹配既有跳过并登记 SQLite 证据。生成与实际核心 TRX 同形的正例，包含 `notExecuted=0` 的汇总及两个具名 `NotExecuted`，应报告汇总差异且通过。用缺失或不可读的 TRX、无明细或零匹配、意外跳过及矛盾的关键计数验证入口非零及套件诊断。用 `python3 eng/tests/run_verify_r0_tests.py` 执行仅用 Python 和可在仓库内生成的夹具构成的定向用例，显式检查 `TestResult`，确保失败或零有效执行返回非零。
