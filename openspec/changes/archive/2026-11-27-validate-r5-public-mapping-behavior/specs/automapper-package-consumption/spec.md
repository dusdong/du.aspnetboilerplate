## ADDED Requirements

### Requirement: 消费者可在同一 .NET 10 环境对照两代公开映射包

消费者 SHALL 能只用公开输入，用固定模板的 DTO、实体和 Profile，分别在 R4 与 R5 独立消费者中运行映射用例，核对实际加载的发行包，并将每个业务结果与预先登记的期望比较。

#### Scenario: 从两次独立还原确认公开发行身份

- **WHEN** 消费者使用同一份业务代码、SDK、运行时和 SQLite Provider，在各自的空缓存从 nuget.org 还原，只在三个映射包中直接引用该版适配器
- **THEN** 两侧分别解析到对应发行组合，三包的精确依赖边命中，实际消费的维护主包可逐个核对公开签后摘要，两张业务包图的包版本差异仅有三个映射包
- **AND** 各自记录三份映射程序集的所选包内资产、输出和加载文件摘要，调用结束时枚举全部加载上下文，每侧进程只加载一个引擎实例

#### Scenario: 独立消费者更新已有用户与按键集合

- **WHEN** 两版各自通过经典 ABP 的模块配置和 `IObjectMapper`，将 `IsActive = true` 的 `UserDto` 映射到 `IsActive = false` 的已有 `User`，并执行相同的按键集合映射
- **THEN** 各自返回原用户，其 `IsActive` 变为 `true`，其他普通字段命中输入，原角色集合、角色对象和创建时间保留
- **AND** 各自保留目标集合和键 10 的原对象并更新其值，删除键 20，创建一个键 30，最终有序键值为 `10:updated`、`30:inserted`

#### Scenario: 将同一查询实际发送给 SQLite 并物化

- **WHEN** 两侧以相同种子启动各自的 SQLite 数据库，对租户 6 的活跃用户执行 `ProjectTo<UserDto>` 并物化
- **THEN** 两侧各自捕获执行 SQL 和参数，核对租户、活跃条件、排序、读取列及其顺序，物化 ID 依次为 12、13、11，各 DTO 字段符合种子预期
- **AND** 投影表达式与真实取列证实 `FullName` 由客户端访问实体属性计算。SQL 别名和空白差异允许通过

#### Scenario: 输入或业务未达到约定

- **WHEN** 一侧包身份、运行环境或依赖图不符合对照条件，或一项业务断言失败、缺失或跳过
- **THEN** 验收入口返回非零，报告注明版本、阶段、预期和实测；输入校验失败时该侧不计入业务结果，已有原始输出可供定位与复测

#### Scenario: 第一侧物化后投影断言失败，第二侧独立完成

- **WHEN** 在定向反例中只交换第一侧预期列中的两列，两侧真实探针分别执行相同的 SQLite 查询并物化
- **THEN** 第一侧报告保留已通过的用户更新和按键集合结果，标记投影失败，列出预期和实际列顺序，并可回读实际 SQL、参数、投影表达式和物化行
- **AND** 第二侧独立完成全部三项并留下通过记录。总报告分别列出两侧状态和退出码，总入口返回非零
