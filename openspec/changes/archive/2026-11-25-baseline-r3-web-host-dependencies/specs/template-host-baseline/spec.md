# 模板 Web.Host 基线

## Purpose

维护者可重复构建固定模板的原版后端，核对源码声明、实际依赖和构建产物，并在补齐维护版包前取得可复核的参照。证据覆盖单一入口的编译与依赖范围，支持后续对比候选包迁移的影响。

## ADDED Requirements

### Requirement: 固定模板入口可独立还原和构建

主仓 SHALL 提供可复跑的 Web.Host 基线命令，在受测环境中从固定模板提交隔离物化源码、干净还原，并用同一输入及还原产物完成 `net9.0` Release 构建。

#### Scenario: 从独立空缓存构建原版 Host

- **WHEN** 固定模板 Git 对象和指定 SDK 可用，维护者在 macOS ARM64 上运行基线命令
- **THEN** 命令从固定提交取得包含 Web.Host 的原版源码，使用独立的空缓存和显式仅含 nuget.org 的 NuGet 配置还原，并按 `--no-restore` 构建同一份源码
- **AND** 报告登记主仓输入、模板与框架提交和树、工具版本、平台、有效包源、实际命令和退出码，并记载原模板与有效 NuGet 配置的差异
- **AND** 结果标明 SQL Server 为模板声明的 Provider，并把宿主启动、数据库操作及 Angular 构建记录为未执行

#### Scenario: 固定输入或构建条件不满足

- **WHEN** 固定模板对象或入口不可用、环境不符合要求，或还原或构建命令失败
- **THEN** 命令返回非零，报告失败的输入、条件或步骤，并保留当次可取得的日志和未执行范围

### Requirement: 依赖证据可追溯到实际还原与 Host 输出

主仓 SHALL 从五个可达项目的实际还原资产与最终 Release Host 的依赖清单和输出提取证据，逐项呈现包的声明、解析版本、依赖关系、来源、内容标识和资产用途。

#### Scenario: 核对模板直接依赖和传递资产

- **WHEN** 固定入口成功还原和构建
- **THEN** 证据包含 Web.Host、Web.Core、Application、EntityFrameworkCore、Core 各自的 `net9.0` 还原图。六个原版 ABP ID 须保持固定源码声明，分别记录还原范围和实际解析版本。直接与传递包均可按 ID、已解析版本、来源、内容哈希和依赖边核对
- **AND** SDK 构建输入单列。对 `downloadDependencies` 中实际下载的包核对 ID、版本、来源和可得哈希；使用预装 pack 时记录实际身份、版本及可得证据，对缺少的来源或哈希注明原因
- **AND** 证据对照项目选中的编译、运行和构建资产，并区分私有、工具和共享框架等用途。Host `.deps.json` 的入口、项目和包依赖边可追溯到同轮还原图的实际解析。使用 SDK 运行复制清单核对包括 SQL Server Provider 在内的运行声明与实际输出，核对框架运行 DLL 的路径和 SHA-256，再由每个实际输出反查唯一包、版本和资产路径

#### Scenario: 命令成功但证据不完整或归属冲突

- **WHEN** 任一必需项目资产、Host 依赖清单或输出缺失、不可读、零匹配，或者存在无法归因的运行库、依赖边或资产差异、框架资产来源冲突或维护版 ABP 包混入
- **THEN** 命令返回非零，报告指向具体项目、目标、包或资产，并留存已取得的原始证据
- **AND** 第三方实际解析差异按依赖边、版本和资产归属逐项记录，供维护者审查

#### Scenario: 单个必需的框架运行 DLL 缺失

- **WHEN** 证据副本保留有效的 Host `.deps.json` 和其余输出，仅移走应当复制的 `Abp.Castle.Log4Net.dll`
- **THEN** 输出核对返回非零，报告指出缺失的 `Abp.Castle.Log4Net.dll` 及其预期路径

#### Scenario: 在另一工作站比较首次通过的基线

- **WHEN** 维护者在另一工作站检出主仓并准备核对新的 Host 构建
- **THEN** 随验收文档保存的首次通过清单可按项目和目标比较项目引用、直接包声明与解析版本，以及应用包 ID、版本和包间依赖边。框架运行 DLL 可按相对路径、所属包与 SHA-256 比较，SDK 构建输入单列
- **AND** 清单内容可逐项对应首次通过的还原和输出证据，比较时无需读取原工作站的绝对路径或私有缓存；复跑结果保存在各自的证据目录

### Requirement: 模板闭包的候选包缺口可用于后续迁移

主仓 SHALL 将原版 Host 实际包闭包与当前框架源码依赖及已验核心包映射对照，保存可用于安排补包和验收的缺口清单。

#### Scenario: 区分已验核心包、源码预期和模板实测

- **WHEN** 维护者复核首包验收证据
- **THEN** 可分别核对模板的实际原版解析、框架源码的项目引用与目标、R2 五包的已验身份及对应资产，以及剩余六个框架项目涉及的候选包缺口
- **AND** 若实际解析发现预期之外的框架包、版本关系或资产归属，报告可定位差异，验收前完成归因并据此决定后续范围
- **AND** 补包记录按依赖关系说明独立的 SignalR 和 Log4Net、Module Zero 次序、AutoMapper 兼容维护条件，以及同批候选、迁移、运行验证和回退各自的准入条件
