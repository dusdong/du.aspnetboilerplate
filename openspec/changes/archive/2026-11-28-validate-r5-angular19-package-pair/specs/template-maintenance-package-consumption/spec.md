# Spec Delta

## ADDED Requirements

### Requirement: 固定 Angular 19 模板可同时验收两份本地 npm 候选

验收 SHALL 在固定免费模板与 Angular `19.2.1` 的隔离环境中同时冻结安装已登记的 `abp-ng2-module 12.1.0` 和 `abp-web-resources 6.1.0` 本地实包。以同一次新 production 构建证明两份包的实际消费，并以同阶段的资源单包输出及限定的浏览器证据判断该组合。

#### Scenario: 在同一固定模板从空缓存实际安装两份候选

- **WHEN** 使用登记的模板提交、工具链和两份已核验的候选 tarball，在新目录和独立空缓存执行冻结安装
- **THEN** 两个目标依赖分别解析到指定本地归档，实装的完整相对路径及原字节摘要分别匹配候选归档。临时锁在冻结安装前后及构建后保持相同。模板源码与构建配置身份一致，除两个目标包的预期替换外，锁解析和实际依赖图与可比对照等价
- **AND** 归档摘要和包内文件身份分别记录。复跑归档摘要偏离时，记录差异原因及逐项文件证据，包内容漂移须以不同候选登记

#### Scenario: 同一次 Production 构建可追溯两份实包

- **WHEN** 从已核验的实装按模板原 production 配置生成新输出
- **THEN** 构建成功，模板解析到实装适配器声明及实装资源包的两份显式声明。构建统计或同次构建的等效证据表明候选 FESM 对某个实际生成的浏览器 JS 有非零代码贡献
- **AND** 同次构建的实际全局脚本读取保持模板顺序，`abp.js` 和 `abp.moment.js` 可从实装追溯至统计入口及 HTML 所引用的产物。两份 SignalR 静态资产的原始字节逐项匹配候选归档和实装

#### Scenario: 同阶段浏览器目录及历史静态观察可独立核对

- **WHEN** 将双候选的完整 `dist/browser/` 与仅换资源的有效对照在同一配置阶段逐路径逐字节比较
- **THEN** 报告核对字体输入和应用配置处理阶段，逐项记录新增、缺失和字节变化的成因、影响及可核验的接受依据。若原始对照缺失，以登记的资源单包输入重建可比对照并记录其来源
- **AND** 仅在两侧完整目录的路径集合与各文件原字节逐项相同、相关输入与静态服务条件等价、历史最小页及三条浏览器回执和实收原件与本轮产物吻合时，才可引用历史静态观察。否则，验收通过所需的静态证据须用本轮产物在回环静态服务和独立浏览器上下文重跑最小页取得
- **AND** 两种证据均须证明 `window.abp.utils.formatString('ABP {0} / {1}', 'R5', '资源')` 精确返回 `ABP R5 / 资源`，页面未捕获异常为零，本轮 `index.html` 全局脚本标签所指的 URL 及 `/assets/abp/abp.signalr.js`、`/assets/abp/abp.signalr-client.js` 均返回 HTTP 200，三份浏览器响应原字节分别匹配本轮 `dist/browser/` 对应文件并保留 BOM。结果标明历史引用或本轮实跑。最小页通过仅证明上述静态观察，其他产物差异仍须逐项判定

#### Scenario: 身份、来源或消费证据不足

- **WHEN** 输入不可用，冻结身份或可比性失配，发现无法解释的构建差异，或实际安装、构建、产物来源、静态观察未满足要求
- **THEN** 记录具体阶段、预期和实测、可用回执与原因。候选代码所在的 chunk 或其他产物（包括资产）有差异且缺少可核验的接受依据时，组合待查。确认产物差异违反验收要求时，组合失败。依赖该条件的步骤标记未执行。只有安装、同次构建、产物逐项对照及限定静态观察均有符合条件的证据时，双候选验收才判通过
- **AND** 原角色编辑继续使用登记的公开冻结输入及原有清单和静态实物校验
