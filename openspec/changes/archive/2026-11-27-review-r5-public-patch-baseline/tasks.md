# R5 公开补丁后的维护审查任务

## 1. 固定公开输入

- [x] 1.1 在主仓编写 `docs/maintenance/r5-public-patch-review.md`。核对标签解引用、三个生产 gitlink、固定模板、公开附件摘要，按 ID、版本及签后摘要对齐三个更新包和十个沿用包。
- [x] 1.2 核对公开升级报告与四份入口原图，附原图定位、摘要及可复算的依赖差异表。对每个 TFM 的 Web.Host 和 Migrator 分别列出直接、传递依赖和对应引入路径，逐项解释相对 R4 的版本、依赖边及所选资产变化。遇到缺图或摘要失配时，按设计中对应 TFM 的公开源构建入口补图，单列重建证据与历史原图的缺项。

## 2. 判断本版适用性

- [x] 2.1 从三个上游仓库的六条分支终点续查提交、发行与仓库公告。记录各分支起止 SHA、查询时间及相关变动，涉及已回补项时对照本版生产源码和实包证据。逐项接续上轮暂缓或待核实的上游问题，即使分支未变也登记原复查条件、本轮是否满足、处置依据及对整轮补丁决定的影响。
- [x] 2.2 对四图的完整包集按实际 ID 和解析版本重查 NuGet 与 GitHub 公告。对维护包另按上游原包 ID 取回公告，以上游基点版本匹配区间。按入口列出两组 ID 和版本、基点提交、命中项的本版源码及实包处置依据，并记下查询覆盖、分页终点、修订、撤回或缺项。
- [x] 2.3 按四入口实测的两套共享框架接续 Microsoft 服务公告。补查 CVE-2026-56158 的组件、版本范围和修订日期，给出消费者行动；证据仍不足时，注明影响哪项判断及补查入口。

## 3. 交付维护决定

- [x] 3.1 在审查记录和维护路线公布需补丁、无需补丁或暂不能判定的结论，分别列出维护包、模板、运行环境和应用的行动与下一检查点。回读关键摘要、四图和引用，运行 `openspec-cn validate --all --strict --no-interactive`，登记实际结果与未验证项。
