# 公开 R4、R5 同库切换的验证设计

## Context

现有 `eng/r5_template_consumer.py switch` 的中段从本地候选源还原，首尾从公开 R4 还原；纯公开 R5 已有 `build`、`install`、`upgrade` 入口。现有 `run_phase` 只在首段创建一个用户，后两段查询同一用户。公开 R5 同库升级实测的是两代运行时接续同一包组合。这些报告均有各自的输入和范围。[验收入口](../../../../eng/r5_template_consumer.py) · [公开消费结果](../../../../docs/maintenance/r5-public-release.md#公开消费与回退证据)

## Goals / Non-Goals

目标是让应用维护者判断在同一隔离库中切回上一组包能否保留补丁期间的业务写入。固定模板 `2e953687`、macOS ARM64、`net10.0`、.NET 与 ASP.NET Core `10.0.15`、SQL Server Developer `16.0.4236.2` 及同一 Angular 产物。换运行时、从备份恢复或扩大平台支持各有独立证据；此处只验证换包这一项变量。

## Decisions

1. **单列公开切换入口。** 在既有主仓消费者增加 `switch-public`，复用 R4 公开构建、R5 公开构建和现有 SQL、浏览器、进程观测。保留历史 `switch` 的混合源输入及用例。两版发行输入分别命名和校验，避免把供 R4 阶段使用的下载登记传给 R5 阶段。[R4 消费者](../../../../eng/r4_template_consumer.py) · [R5 消费者](../../../../eng/r5_template_consumer.py)
2. **按阶段绑定公开资产。** 通过两版公开校验附件核对标签、协调提交和签后下载登记；验收机的冻结件可作内容对照。每阶段从独立空缓存仅用 nuget.org 还原，记录实际来源。Web.Host 的 13 包、Migrator 的 10 包各按自己的子集比对。引擎、Collection、适配器依次从 `14.0.0 / 11.0.0 / 10.5.1` 换到 `14.0.1 / 11.0.1 / 10.5.2` 后换回；按 ID 比对十个沿用包的签后摘要。现有 `build_public` 核对整张 R4 下载表，公开切换需分别验证两张表，仅对沿用包跨版本要求摘要一致。每个阶段对账编译、输出与实际加载的资产，保留 Migrator 中只进入输出的 DLL 状态。

   逐入口比较三阶段完整的 `net10.0` 图，并对照上轮 Web.Host 94 包、Migrator 66 包的公开基线。按包 ID 比较解析版本，按父子节点比较依赖边及其版本约束，按包内相对路径、用途及内容摘要比较所选包资产。独立缓存的绝对路径另行记录。首末 R4 应一致；中段 R5 的预期差异是三个映射包的版本及对应 DLL 摘要、四条边的精确版本约束。发现其他差异时，在报告中列明并追查来源。[上轮完整图与已知差异](../../../../docs/maintenance/r5-public-patch-review.md#解析版本依赖边和所选资产)
3. **逐人核对写入和查询。** 在独立新库用 R4 应用创建 A。R5 接续同库后查回 A，再创建并查回 B。每次 `User/Create` 成功返回，立即保存该阶段、租户、唯一用户名和返回的用户 ID，随后记录数据库读回的创建者和业务字段。切回 R4 时运行该版 Migrator 和 Web.Host，由同一租户管理员在新的 Angular 会话中确认 `Pages.Users`，用两人的独立关键词各查一次。

   每次查询分配独立请求标识，按阶段和用户分别保存结果。用创建回执核对授权响应中的 ID 和业务字段、页面显示的唯一用户名，并用请求标识关联实际 Host PID 及该次计数和列表查询的 SQL 连接。各阶段核对同库身份、Migrator 连接和 30 条迁移历史。按实际认证次数对账成功登录行；末段在同一会话中查两人，浏览器成功登录只增加一行。

## Risks / Trade-offs

- 签前候选与签后包可能含相同 DLL，来源或签后归档摘要错误须在操作测试库前报告。公开源暂时不可读时保留失败阶段，新一次运行从独立目录重新取证。
- 定向覆盖 R5 创建 B 已返回 ID、随后授权查询失败的时点。失败报告保留创建回执，标明数据库读回是已取得还是缺失，登记失败的查询和未执行的末段 R4。再次验收使用新一轮独立测试库和用户名，便于区分两次写入。
- 本轮手册仅在实跑通过后更新支持结论，并说明切回 R4 同时恢复旧集合映射行为。业务回退的范围限定为已观测的用户和登录写入。[候选阶段的历史边界](../../../../docs/maintenance/r5-automapper-template.md#支持范围与公开发行交接)
