# 公开映射包切换与同库回退

## MODIFIED Requirements

### Requirement: 固定模板的补丁结论绑定同批实包

模板验收 SHALL 将两代 Web.Host 和 Migrator 的实际包图、Release 资产、按需加载状态和业务观测绑定到同一份补丁组合。报告分别列出本轮实测及引用的历史证据。

#### Scenario: 新库安装及同库接续

- **WHEN** 用固定模板在独立新库上执行 `net10.0` 安装，并在独立迁移用例中由 `net9.0` 向 `net10.0` 接续同一 SQL Server 库
- **THEN** 新库迁移及 Host HTTP 检查通过，两代的 Host 和 Migrator 分别核对 13、10 个维护包。冻结客户端复验租户登录和授权用户查询，记录命中的数据库、预期用户及迁移前后数据变化

#### Scenario: 在固定运行时与同库上切换补丁并回退

- **WHEN** 固定模板在同一个隔离 SQL Server 库上按 `net10.0` 依次运行完整的公开 R4 组合、三个候选加十个 R4 包、完整的公开 R4 组合，并在首阶段写入可识别的业务记录
- **THEN** 候选和回退阶段均通过授权查询命中同一数据库、租户和业务记录，确认记录身份与数据。三阶段分别对账 Web.Host 和 Migrator 在各自入口范围内的包图、编译、Release 输出及按需实际加载，回退恢复公开 R4 的包版本及资产
- **AND** 记录旧版集合行为的局限、三阶段数据库状态与写入边界。若另行验证备份恢复，另记所选恢复点及其后的写入影响

#### Scenario: 切回公开旧版后仍可查询新版写入

- **WHEN** 固定模板在同一隔离 SQL Server 库、同一客户端和两套共享框架 `10.0.15` 上依次运行公开 R4、公开 R5、公开 R4，R4 和 R5 分别通过各自的应用在同一租户创建一个不同用户
- **THEN** 三阶段从独立空缓存仅用 nuget.org 还原，按各自发行的签后摘要核对 Web.Host 的 13 个、Migrator 的 10 个维护包及对应输出和实际加载资产。逐入口比较完整 `net10.0` 图的包 ID、解析版本、依赖边及约束和所选包资产，忽略缓存根路径差异。首末 R4 的图和包资产摘要一致，中段 R5 的差异限于已登记的三个映射包版本及对应 DLL 摘要、四条边的版本约束
- **AND** R5 查回 A，创建并查回 B。切回 R4 后，同一租户管理员在一个新登录的 Angular 会话中分别查询 A、B。报告为两次查询保留不同的请求标识及可独立回读的证据，各自关联创建回执、响应中的用户 ID 和业务字段、页面用户名、实际 Host 和查询连接
- **AND** 三阶段沿用同一数据库状态，报告核对 Migrator 的迁移连接、数据库身份、30 条迁移历史及各阶段的成功登录行。末段两次查询共用一次浏览器登录

#### Scenario: 包来源或业务读取无法对账

- **WHEN** 任一阶段的包源或签后摘要偏离发行记录，迁移或业务查询落在其他库，或授权查询无法唯一命中预期业务记录
- **THEN** 报告指出具体阶段、预期与实测值或缺失证据；包输入不符时在数据库操作前停止，业务阶段失败时记录已取得的写入证据和未执行步骤。只有三阶段均通过才登记该固定组合支持同库包回退

#### Scenario: R5 创建成功后授权查询失败

- **WHEN** R5 的 `User/Create` 已返回用户 B 的 ID，随后对 B 的授权查询失败
- **THEN** 失败报告仍可回读 R5 阶段、租户、用户名和创建返回的 ID，注明数据库读回结果或证据缺失，并分别标记该查询失败、末段 R4 未执行
