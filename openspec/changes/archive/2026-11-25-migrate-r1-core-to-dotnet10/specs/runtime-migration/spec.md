# 核心源码运行时迁移

## Purpose

维护者需要在升级核心框架运行时时，核对现有源码入口、程序集契约和实际业务回归。候选源码按实测环境和依赖组合验收，为后续独立包交付提供可追溯的输入。

## ADDED Requirements

### Requirement: 首批核心源码可在 .NET 10 构建

首批五个核心框架项目及其三套回归的项目引用闭包 SHALL 可使用稳定 .NET 10 SDK 干净还原，并生成使用 ASP.NET Core 10 和 EF Core 10 的 Release 产物。

#### Scenario: 还原并构建核心源码候选

- **WHEN** 在受测环境中从候选树还原并构建首批源码
- **THEN** 所有闭包项目均有 `net10.0` 的实际还原和构建证据，适用的框架及 Provider 依赖均解析至指定的 10.0 版本线
- **AND** 五份核心 DLL 保留批准的程序集身份和已有公开类型全名，可逐项核对公共 API 与资源变化

### Requirement: 同仓既有源码引用可继续使用 .NET 9

首批迁移 SHALL 保持现有 `net9.0` 源码调用方对核心项目和测试基座的项目引用可用。

#### Scenario: 原调用方还原和构建

- **WHEN** 选定的原调用方按各自默认目标还原、编译和运行适用的定向回归
- **THEN** 它们解析到候选树相应的 `net9.0` 产物及兼容依赖，保留原有公开调用路径
- **AND** Module Zero 调用原有批量更新 API 时，本轮 `net9.0` TRX 中按全名核对的四项既有用例均为 `Passed`，覆盖当前租户的更新范围、调用方谓词，以及启用和禁用 `MayHaveTenant` 过滤器的行为

#### Scenario: Windows 构建默认解决方案

- **WHEN** 在 Windows CI 或获准的等价 Windows 节点上验证同一候选的默认解决方案
- **THEN** 解决方案可以完成还原、构建和测试，证据包含所用提交、运行时和实际结果，GitHub 工作流的接单及结果按实际记录列示

### Requirement: 新运行时保持已验收核心行为

候选 SHALL 在新运行时运行核心、ASP.NET Core 和 EF Core 三套完整回归，对照迁移前已接受的补丁基线，并继续满足 `efcore-query-filters` 规范 的行为契约。

#### Scenario: 检查真实运行结果与已验收用例

- **WHEN** 维护者对同一 Release 候选运行三套完整回归，其中关系型 EF 查询使用真实 SQLite
- **THEN** 三份当次 `net10.0` TRX 的明细可追溯到已验收套件和查询过滤用例，既有预期继续通过，跳过仅限既有两项具名用例
- **AND** 缺失、零匹配、新增跳过、失败或待解释的用例差异使该轮候选暂不能验收

#### Scenario: EF Core 10 查询表达式编译保留过滤上下文作用域

- **WHEN** 通过两参数 `CompileQueryExpression<TResult>(Expression, bool)` 编译查询，分别传入同步和异步标志
- **THEN** 内部服务收到原查询表达式和标志，已授权查询在编译期间可读取绑定的 DbContext，嵌套的未授权查询无法读取外层上下文
- **AND** 内部服务正常返回或抛出异常后，调用前的上下文均得到恢复，调用方收到内部服务返回的表达式或抛出的异常

#### Scenario: 复核候选的覆盖范围

- **WHEN** 已取得实际还原图、五份核心 DLL 和本轮回归结果
- **THEN** 验收记录将结果关联到实际验证的候选树、SDK、运行时、平台、Provider 和原始证据，并列明各项未执行的验证
