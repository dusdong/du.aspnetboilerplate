# R3 原版模板运行对照任务

## 1. 固定构建与运行输入

- [x] 1.1 在主仓接入原版模板运行 profile，复用固定源码和 Host 构建验收，补充同提交 Migrator 的独立还原、Release 构建与输出摘要。核对实际要启动的 Host 与当轮 11 个原版 ABP 包及 SQL Server Provider 相符。准备数据和两轮验收时显式以 `Development` 启动同一 Release Host，从启动记录核对并登记实际环境名。
- [x] 1.2 从模板锁文件干净安装并以 production 配置构建 Angular，登记工具与安装版本、锁文件和产物摘要。用运行时配置对齐前端地址、后端地址与 CORS，验证浏览器能从当轮输出加载页面并请求本轮 Host 的应用配置。
- [x] 1.3 为验收入口提供复跑说明和阶段报告，记录必需的外部输入、配置注入与脱敏方式。定向检查错误模板输入或锁文件变动会失败，报告中指出输入与阶段。

## 2. 准备原版 SQL Server 恢复点

- [x] 2.1 预检专用实例、本轮源库和新恢复库目标，核对实际备份/恢复能力。对源库运行固定 Migrator 和种子，读回迁移历史、租户和管理员身份。用错误目标或缺失种子场景确认可定位失败。
- [x] 2.2 建立合成用户和租户登录场景。用数据库核对搜索词在本租户可见用户的用户名、姓名和邮箱中仅匹配目标用户，记录预期字段及登录账号的权限依据。结束准备会话，在首轮验收登录前保存备份，登记恢复标识、摘要和实际备份方法。

## 3. 比较两轮真实浏览器结果

- [x] 3.1 在源库启动原版 Host，以全新 Angular 浏览器会话选择租户、登录、搜索用户。核对认证结果、会话租户与登录用户 ID 及权限。捕获搜索触发且带预期 `Keyword` 的 `User/GetAll` 请求，核对总数为 1、唯一响应项的 `(id, userName)` 及唯一结果行的用户名单元格，保存首轮脱敏报告。
- [x] 3.2 把同一份备份实际恢复至另一新库，读回并比较迁移历史及登记的业务字段。将连接切换到恢复库，重启同一 Release Host。使用同一前端产物和全新浏览器会话复跑 3.1 的登录与搜索，比较两轮结果。第二轮登录前后分别读回两库中该租户账号的成功登录计数，核对恢复库增加 1、源库增量为 0。定向检查误连源库、错租户、仅有初始列表或缺少预期行时，入口返回非零并报告差异。
- [x] 3.3 按维护文档验证备份和复跑入口均可定位，发布本地验收记录、首轮与恢复轮结果、适用环境及未执行范围。核对本轮进程和端口已释放，运行 OpenSpec 全量严格校验，通过后在路线中登记进入同目标换包的证据。
