# 原版应用回退任务

## 1. 登记原版应用与恢复介质

- [x] 1.1 在主仓 `eng/verify.py` 接入独立回退 profile。按原版返修报告核对固定模板、Web.Host 和 Migrator 的 Release 清单、包来源及冻结前端，向复跑手册写入输入位置和核验命令。检验误传 .NET 9 维护版产物时入口能识别同名 DLL 的来源差异。
- [x] 1.2 登记升级正式报告及两份介质的角色、摘要和备份集 ID。复用专用 SQL 恢复入口建立两个新库，逐库核对实际身份、文件、30 条迁移、业务表目录和授权，按规范列出的七个字段与恢复点的成功登录行逐行比较。验证备份互换或目标已占用会在相应阶段失败，在手册中记下正确的起点。

## 2. 在两个数据状态上切回原版

- [x] 2.1 为原版 Migrator 与 Host 接入进程观测，按各自原版资产核对入口、共享框架和 SQL 运行链。保留迁移命令的 PID、实例及库名，以及维护版 Migrator 连正确库和原版 Migrator 连错库的负例。将关键词请求、Host PID、计数及列表命令的实际读取库关联起来，验证读到对照库、缺少连接记录及误用初始列表记录时均能拒绝。
- [x] 2.2 在升级后库运行原版 Migrator、Host 和真实 Angular 登录、授权、关键词查询，记录迁移前后结构、查询的实际读取库及响应。核对保留行 1、2、3，仅新增本次成功登录，对照库逐行保持原值。保存可重放的运行命令与该路径结果。
- [x] 2.3 在升级前库用相同应用和新会话核实迁移、权限、关键词查询的实际读取库、用户 3 和页面结果。按七个字段核对保留行 1、2 及唯一新增行。以登录后新增行重用 ID 3 且创建时间不同为通过用例。另验两个拒绝用例，分别要求在登录前发现升级轮原行 3 时停止认证，在本轮写入对照库时判定路径失败。
- [x] 2.4 在独立诊断中让升级后路径真实登录成功后发生关键词查询失败。核对首错、认证前快照和清理前实读的两库行差，目标库新增一行、对照库保持原值。用独立核准的目标库和对照库单独跑完升级前路径，确认汇总保留两条路径各自的结果，并区分诊断与正式验收。
