# template-runtime-baseline Specification

## Purpose

让维护者在替换经典框架包之前，可以用固定版本的原版客户端、宿主和测试数据库重现一次真实租户登录及授权查询，并从同一恢复点重新取得可比较的业务结果。

## Requirements

### Requirement: 原版运行输入可核对

验证入口 SHALL 从固定模板构建原版 Web.Host、Migrator 和 Angular 客户端，关联实际运行的产物、工具版本、包解析和配置。

#### Scenario: 从干净输入启动原版前后端

- **WHEN** 维护者在登记环境从干净目录运行原版对照
- **THEN** 报告能将正在使用的 Host 及前端产物追溯至固定模板提交和当次构建，核对 `net9.0` Host 的 11 个原版 ABP 包、SQL Server Provider、Angular 锁文件和实际安装版本
- **AND** 两轮使用同一套 Release Host 和 Angular production 产物。分别从两轮 Host 的启动记录核对 ASP.NET Core 环境名，均须为 `Development`
- **AND** 报告记录实际 SDK、共享运行时、Node、Yarn、浏览器和 SQL Server 版本，以及用于本轮的前后端地址、数据库标识和脱敏配置差异

#### Scenario: 运行输入与固定基线不符

- **WHEN** 包图混入维护候选、Angular 安装需改写锁文件，Host 实际环境与约定不符，或正在提供请求的宿主与本轮产物不符
- **THEN** 入口返回非零并指出不一致的输入及未执行阶段

### Requirement: 原版数据起点可恢复到独立 SQL Server 测试库

维护者 SHALL 能用模板迁移及种子建立专用测试库，并在首次计入验收的登录前保存可供下一轮复用的恢复点。

#### Scenario: 在新库验证恢复点

- **WHEN** 将已完成迁移并准备好测试租户、授权账号与预期用户的数据库备份恢复到另一独立库名
- **THEN** 报告保留备份标识、摘要、实际还原结果和两库标识，从源库及恢复库分别读回一致的迁移历史、租户 ID、账号 ID、预期用户 ID 和对应角色或权限依据

#### Scenario: 恢复轮登录写入恢复库

- **WHEN** 恢复库的迁移和业务数据核对通过，验收入口在第二轮浏览器提交登录前，分别从源库和恢复库读取该租户、该登录账号在 `AbpUserLoginAttempts` 中的成功记录数
- **THEN** 该账号完成一次成功登录后，恢复库的成功记录数较登录前增加 1，源库的成功记录数与登录前相同。报告保存两库标识及各自的前后计数
- **AND** 若 Host 仍向源库写入或恢复库的增量不符，即使页面和接口都返回预期用户，入口也返回非零并报告两库的实际增量

#### Scenario: 数据起点不成立

- **WHEN** 目标库不属于本轮、迁移或种子不完整、恢复介质不可访问，或新库缺少已登记的测试记录
- **THEN** 该阶段失败并记录具体差异，跳过依赖该数据起点的运行。已存在的非本轮数据库不得被覆盖

### Requirement: 真实 Angular 会话可查询指定租户用户

原版客户端 SHALL 经 Web.Host 完成租户登录，并使用该会话在受 `Pages.Users` 保护的用户列表显示预期的 SQL Server 测试用户。

#### Scenario: 在首轮库和恢复库分别登录与查询

- **WHEN** 原版 Host 分别连接首轮库与已核对的恢复库，使用两个全新的浏览器会话在模板登录页选择同一租户、提交测试账号并进入用户列表
- **THEN** 每轮的真实认证均成功，服务端会话中的登录用户和租户标识与期望一致，客户端具有 `Pages.Users`
- **AND** 提交搜索后，浏览器发出 `Keyword` 等于唯一合成用户名的 `User/GetAll` 请求。该请求成功，响应的 `result.totalCount` 为 1，`result.items` 中唯一项的 `(id, userName)` 与数据库预期记录一致
- **AND** 搜索结果表格只有一条数据行，其用户名单元格文本与预期用户名精确相等。两轮均记录搜索词、响应中的业务字段及页面用户名

#### Scenario: 接口可达但业务未完成

- **WHEN** 浏览器进入了错误租户、仅加载页面外壳或初始列表、未发出带预期 `Keyword` 的请求、查询失败、返回多条或错误记录，或预期用户名未出现在结果行的用户名单元格
- **THEN** 即使 HTTP 端口可用或浏览器正常退出，入口仍返回非零并定位缺失的业务结果

### Requirement: 换包可复用同一组对照证据

验证入口 SHALL 输出可重放的对照记录，将每轮的输入、数据库、浏览器动作、比较字段和退出状态关联到同一次执行。

#### Scenario: 交给下一轮执行相同场景

- **WHEN** 两轮都通过，维护者按文档定位冻结的模板输入和备份
- **THEN** 可取得恢复与启动步骤、原版实际版本、已知业务预期、两轮脱敏结果和可定位的失败诊断。摘要和运行输出可核对，证据不含登录口令、访问令牌、会话 Cookie 或带凭据的连接串
